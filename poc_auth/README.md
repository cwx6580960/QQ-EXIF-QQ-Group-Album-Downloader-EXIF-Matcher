# QQ 登录与群相册会话 POC

这一目录先验证“如何安全、稳定地取得可访问 QQ 群相册的会话”，暂不把登录代码并入正式归档程序。

## 结论与候选方案

### POC A：腾讯二维码登录

程序请求腾讯 `ptlogin2` 二维码，用户用手机 QQ 扫码并确认。成功后由腾讯跳转返回 Qzone 会话 Cookie。

优点：

- 不要求读取浏览器或 QQ 客户端数据。
- 不接触账号密码。
- 用户确认过程清晰，适合成为正式程序的默认登录方式。

风险：

- 腾讯可能调整 `appid`、登录参数或风控流程。
- 登录成功不代表群相册 API 一定接受该会话，因此必须运行群相册探针。

运行：

```powershell
python auth_poc.py qr
python auth_poc.py probe --group 你的QQ群号
```

命令行二维码会通过本地 HTML 打开。图形 POC 直接在窗口中显示二维码。

开发 POC 会优先使用当前 Windows 用户的 DPAPI，把会话保存到 `work\qq-album-session.dpapi`。如果运行环境无法访问 DPAPI 主密钥，会话仅驻留在当前程序内存中，仍可立即执行群相册验票。正式版本优先让隔离的 Chromium/WebView2 配置目录管理会话。

### POC B：QQNT 本地快速登录

QQNT 登录后会在本机提供 `localhost.ptlogin2.qq.com:4301` 快速登录流程。程序请求账号列表和一次性 `clientkey`，再交给腾讯登录跳转地址换取会话。

优点：

- 用户已经登录 QQNT 时操作最少。
- 不读取 QQ 进程内存、数据库或磁盘 Cookie。
- 使用临时票据，不保存 `clientkey`。

风险：

- 依赖 QQNT 仍支持本地快速登录服务。
- 多账号时需要用户明确选择。
- QQNT 或 ptlogin 参数变化时需要维护。

运行：

```powershell
python auth_poc.py local-qq
python auth_poc.py local-qq --uin 你的QQ号
python auth_poc.py probe --group 你的QQ群号
```

### POC C：页面内采集器

`../qq_group_album_collector.user.js` 在用户已经登录的 QQ 群相册页面中运行。它只导出相册元数据和图片地址，不把 Cookie 交给桌面程序。

优点：账号边界最清楚，对登录机制依赖最少。

缺点：需要浏览器能正常打开群相册；QQ 页面结构或接口变化时需要适配。

### POC D：HAR 导入

用户从浏览器开发者工具导出带响应正文的 HAR，桌面程序只解析照片元数据，不读取 Cookie 请求头。

优点：最适合诊断新接口，几乎不依赖自动化登录。

缺点：步骤较多，不适合作为日常主流程。HAR 可能包含敏感请求头，正式导入器应当只读取响应正文，并在导入后提示用户删除原 HAR。

## 明确不采用的方案

- 从 QQNT 进程内存中扫描 Cookie 或票据。
- 解密 Chrome、Edge 或 QQNT 的 Cookie 数据库。
- 要求用户粘贴密码或把 Cookie 上传到服务器。
- 模拟密码登录、绕过二维码确认或验证码。

这些做法安全边界差、维护成本高，也更容易触发账号风控。

## 群相册验票

`probe` 使用参考项目中的群相册列表接口 `qun_list_album_v2`。只有探针能返回目标群的相册数据，登录 POC 才算真正成功。单纯取得 `p_skey` 不作为通过标准。

探针只输出状态码、响应字段和相册数量，不打印 Cookie 值或相册内容。

## 当前推荐顺序

1. 先运行二维码登录 + 群相册探针。
2. 再运行 QQNT 本地快速登录 + 同一探针。
3. 两者都成功时，二维码作为默认方案，QQNT 快速登录作为便捷选项。
4. 如果两者都被群相册拒绝，主方案转为页面内采集器，桌面程序不持有 QQ 会话。

## 图形化验证

双击 `start_auth_poc.cmd`。浏览器会打开本机地址 `http://127.0.0.1:8766/`，页面直接显示二维码，并在过期后自动刷新。登录成功后输入一个你有权访问的 QQ 群号，点击“验证群相册”。
